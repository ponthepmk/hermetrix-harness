## Required failure matrix

- Missing/ambiguous requirements: stop effects, preserve goal, resolve via a new
  requirement revision and explicitly reauthorize changed scope.
- Missing project/directory: refuse dispatch. New source leaves must be explicitly
  writable, with an existing owned parent and host-observed absent preimage.
  Refuse intervening files; roll back exact generated bytes into retained
  quarantine. Missing receipt or newer edits require inspection.
- Changed canonical project root: wait before further goal work; mutation and
  verification bind the captured root and refuse redirected paths.
- Invalid plan, dependency cycle or uncovered criterion: existing host validators
  reject before worker dispatch; plan retries stay bounded and evidence-linked.
- Provider offline/denied/timeout/truncated response: retain operation receipt;
  wait for inspection when the effect outcome is not established. Do not silently
  change the endpoint/model/context or replay its request.
- Stale source, foreign owner, path escape or scope mismatch: refuse mutation.
- Mandatory check failure: retain command output, restore exact preimages and
  feed observed failure evidence into a new attempt. Two matching failures require
  planner escalation; budget exhaustion is not success.
- Reviewer rejection: retain findings, rollback, and require the next attempt to
  address the actual finding. A separate profile using the same model is not
  model-diverse verification.
- Restart, Stop or deadline: cancel owned jobs, retain interrupted/uncertain
  effects, reconcile before another external action; no completion by timeout.
- MT5 missing/history unavailable/stale report/zero trades/localized number:
  nonzero verification outcome with inspectable evidence; never accept mere
  process exit as proof that the business target passed.
- Completion/acceptance stale after later evidence: current subject hash and
  every mandatory gate must pass again.
