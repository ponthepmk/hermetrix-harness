# Hermetrix redesign — Source baseline

วันที่: 2026-09-13 · HEAD ตอนตรวจ: `30a38d8` + working-tree changes ของผู้ใช้

สถานะ: source inspection เพื่อวางแผน ไม่ใช่ผล runtime qualification รอบใหม่ และไม่ใช่การรับรองว่าไม่มีบั๊ก ข้อมูลใน screenshot/รายงานเก่าใช้เป็นประวัติความต้องการ ไม่แทน source ปัจจุบัน

เอกสารชุดนี้เพิ่มเฉพาะ `docs/redesign/` ไม่แก้ source ที่กำลังทำอยู่ อ่านคู่กับ [requirements](2026-09-13-requirements.md) และ [blueprint](2026-09-13-blueprint.md)

## 1. ของเดิมที่ควรรักษาและปรับต่อ

| Session/run authority | `internal/agent/service.go`, `internal/agent/models.go` | contract, per-turn lease, receipts และ transactional persistence ใช้เป็น migration boundary ได้ |

## 2. ช่องว่างหลักที่กระทบ requirement ใหม่

### B01 — 96k ยังไม่เป็น capacity เดียวกันทั้งระบบ

`internal/context/profile.go` มี 32/64/128/256k/1m แต่ไม่มี 96k; `internal/qualification/service.go` ฟังก์ชัน `contextTier`/`contextCapacity` hardcode tier อีกชุด การเพิ่ม dropdown ไม่พอ ต้องมี registry เดียวสำหรับ runtime, qualification และ UI รวมการ invalidate หลักฐานเมื่อ model/runtime/allocation เปลี่ยน

**สถานะแก้ไข 2026-09-16:** เพิ่ม `extended-96k` = 98,304 tokens และให้ qualification ใช้ registry เดียวกับ compiler/UI แล้ว พร้อม unit/race tests; ยังไม่ถือว่า Windows local model ผ่าน 96k จนกว่าจะ probe และ qualification runtime จริง

`internal/localmodel/probe.go:266` อนุญาต probe เฉพาะ loopback ดังนั้น Mac เรียก Windows endpoint ได้ไม่ได้แปลว่าตรวจ Windows allocation ได้แล้ว

### B02 — ขาด task/requirements/plan ที่เป็น state ระยะยาว

`internal/context/types.go` ระบุว่า acceptance criteria เดิมถูกถอดเพราะไม่มี producer; `KindOpenTask` ยังไม่ได้เป็นแผนงานปกติที่มีผู้ผลิตจริง `internal/agent/service.go` สร้าง context decisions จาก approval เป็นหลัก และ pin คำขอล่าสุด ไม่ได้มี authoritative requirement set ที่แก้ revision ได้

`RecoverInterruptedTurns` ทำเครื่องหมาย interrupted turn ล้มเหลว/คืน lease ไม่ได้ resume แผนจาก checkpoint พร้อม reconcile effect ที่ผลยังไม่ทราบ Turn limits ป้องกัน loop ยาว แต่ไม่ใช่ task orchestration

### B03 — learning มีที่เก็บ แต่ evidence และการนำกลับมาใช้ยังมีช่องโหว่

- `agent/service.go:1937` ใน `learningTriggerForTurn`: digest ส่วนใหญ่เป็น event IDs/status; decisions/artifacts/redactions ว่าง และ goal จำกัด 2,000 runes; reviewer ไม่มี evidence hydration สำหรับสาเหตุจริง
- failure trigger สร้างก่อน failure event ถูกบันทึก จึงอาจไม่มีเหตุการณ์สาเหตุอยู่ใน digest; generic failure ที่ไม่ได้ activate skill ไม่ได้เข้า learning ทุกกรณี
- `VerifiedBy` รับ `workspace.run` ที่ exit 0 โดยไม่พิสูจน์ว่าเป็น acceptance check; เช่นคำสั่งดูไฟล์สำเร็จไม่ใช่หลักฐานว่าแก้บั๊กสำเร็จ
- `cmd/hermetrix/main.go` ticker เรียก `DrainPending` กับ curator แต่ไม่ได้เรียก learning `RunNext`; queue ถูกสร้างไม่เท่ากับมี background reviewer ทำงานครบวงจร
- `internal/product/service.go` memory CRUD ยังไม่มี consumer ใน agent/context path ที่ตรวจพบ
- `buildSessionContract` ใน `agent/service.go:177` โหลด active skills โดยไม่ filter `ScopeKind/ScopeRef` ตาม project; ต้องแก้ก่อนเปิด reuse ข้ามงานลูกค้า
- `internal/skills/replay.go` มี behavioral gate ในบาง improve paths แต่ new-skill create ไม่ได้บังคับ gate เดียวกันทั้งหมด; ค่าผล behavioral บางส่วนมาจากผู้เรียก และคะแนนรวมไม่แยก regression รายเคส

จึงต้องแยก “เก็บข้อมูลได้”, “สร้าง candidate ได้”, “ตรวจความถูกต้องได้” และ “ช่วยงานถัดไปจริง” เป็นคนละ milestone

**สถานะแก้ไขบางส่วน 2026-09-16:** background ticker เรียก bounded `RunQueued(1)` แล้วและหยุดเมื่อ foreground preempt/requeue เพื่อไม่วนร้อน ช่องว่างด้าน evidence hydration, acceptance-grade verification, scoped reuse และวัดว่าบทเรียนช่วยงานถัดไปจริงยังคงเปิดอยู่

### B04 — IDE actions ยังไม่เป็น IDE runtime

`internal/web/ui/app.js` ส่วน editor actions สร้าง shell command strings ส่งเข้า human PTY ที่อาจเปลี่ยน cwd/ติดโปรแกรมอื่นแล้ว Format ใช้รอประมาณ 500ms แล้ว reload แทนผลจบจริง Node debug มี inspect flag แต่ไม่มี DAP attach/breakpoints/stack panel Outline เป็น regex; review buffer กับ saved file ไม่ใช่ Git revision review

Document/draft/undo/view lifecycle ยังผูก DOM และ frontend maps; renderer เปลี่ยนไม่ควรทำให้ buffer หรือ session หาย File list มี limit 500 โดยไม่มี pagination ที่ครบ การใช้งาน repo ใหญ่ต้องแสดงสถานะ partial ไม่ซ่อนรายการเงียบ ๆ

อาการ editor ใน screenshot **ยังไม่สรุป root cause** จากภาพ: ต้องตรวจ CSP/runtime-injected styles, editor sizing, visible text/contrast และ document contents จริง ไม่ใช้ test สีอย่างเดียวอ้างว่าแก้แล้ว

### B05 — Windows/native ยังไม่ใช่ parity

`internal/product/terminal_windows.go` คืน unavailable ขณะที่ Unix มี PTY จริง Desktop launcher ปัจจุบันใช้ Chromium app window ไม่ใช่ native package ที่ทดสอบครบทั้งสอง OS ต้องแยก native shell กับ host runtime และทดสอบ ConPTY, process cleanup, IME/clipboard, file watch, sleep/restart และ packaged assets

### B06 — concurrency และ execution ownership ต้องแก้ก่อนขยายงาน

- shared `InferenceGate` ใน `cmd/hermetrix/main.go` ถูกถือใน agent turn ครอบช่วงรอ tools ด้วย; provider คนละ endpoint ยังติด gate เดียวกัน ขณะที่บาง probe/embedding path ไม่เข้าคิวเดียวกัน
- `internal/agent/mcpbridge.go` มี current-session state ที่แชร์ใน bridge; redesign ต้องส่ง immutable task/run/session identity ต่อ request ไม่พึ่ง global current selection
- MCP pool ยังมี mutex acquisition/stdio writes ที่ cancellation ไม่ครอบทุกช่วง และ line frame ใช้ read ก่อนตรวจขนาดทั้งหมด; การแก้ hung read เดิมจึงยังไม่ใช่ bounded I/O ทุกเส้นทาง
- SQLite single connection, repeated history loads/compiled snapshots, command goroutines และ terminal tail updates ต้องวัด queue/WAL/latency แทนสรุปว่า scale ได้จาก unit tests

### B07 — media/desktop control และ long jobs ยังไม่ครบ

Managed browser เป็น CDP browser control ไม่ใช่การควบคุมทุกแอปบน desktop File/text-oriented artifact APIs และ short synchronous tool deadlines ไม่เหมาะกับ multi-GB source videos/render ยาว ต้องมี streaming, artifact references, async job progress/cancel/reconcile และ app-specific integration tests

MCP connection ผ่านไม่ได้รับประกัน OAuth, subscriptions, long-running tasks, interactive inputs หรือความสามารถของแอปตัดต่อ ต้องประกาศ readiness เป็นราย server/feature

### B08 — durability, deletion และ isolation ต้องกำหนดขอบเขตใหม่

`internal/product/backup.go` เป็น backup ของ skill lifecycle ไม่ใช่ full project/task/media recovery การลบ session ไม่ได้เท่ากับถอนบทเรียน/derived data ทั้งหมด ต้องมี lineage และ restore policy

มี auth/token/TLS และ command sandbox แล้ว แต่ PTY/MCP process ไม่ได้ผ่าน boundary เดียวกันทั้งหมด; cwd และ process-tree cleanup ไม่ใช่ filesystem/network sandbox ข้อมูลลูกค้าและ remote device access ต้องมี policy แยกชัด

## 3. ปรับคำกล่าวเก่าให้ตรง baseline ปัจจุบัน

| คำกล่าวเดิม | สถานะที่พบตอนตรวจ |
|---|---|
| รองรับ provider protocol เดียว | ล้าสมัย: มี interface registry และ native Anthropic/Gemini; ยังต้องทดสอบ capability ราย endpoint |
| stdio hung read ไม่มีทาง interrupt | มี kill-on-read-cancel แล้ว แต่ยังต้องตรวจ lock wait/write/oversized frames |
| automatic retry tools/call ซ้ำ | pool ปัจจุบันจำกัด retry เป็น catalog path; ต้องรักษา regression และ uncertain-effect semantics |
| resource/prompt ไม่มี Mcp-Name | ปัจจุบันมีแล้ว; compatibility ใน legacy/stateful paths เป็นอีกประเด็น |
| browser validate แค่ URL แรก | มี redirect/subresource interception แล้ว; ไม่ถือเป็น desktop-wide network isolation |
| ไม่มี auth หรือ sandbox เลย | มีบางระดับแล้ว; ไม่ใช่ multi-user tenant isolation หรือ sandbox ทุก tool |
| ไม่เคยวัด local model จริง | ล้าสมัย: README/ARCHITECTURE บันทึก qwen3:4b ที่ allocation 131,072 แต่ recall 0/5; ไม่ใช่หลักฐานรองรับ 96k บน Windows เครื่องปัจจุบัน |

หลักฐานผลโมเดลย้อนหลัง: [README](../../README.md) และ [ARCHITECTURE](../ARCHITECTURE.md) ระบุ tool grade A แต่ sentinel recall ล้มเหลวหลัง estimated prompt 85,196 tokens ไม่มีการ rerun/ตรวจ raw run artifacts ในรอบวางแผนนี้

## 4. ข้อจำกัดของ test evidence ปัจจุบัน

`internal/web/ui_browser_e2e_test.go` และ browser CI มีประโยชน์ แต่บางเคสข้ามเมื่อไม่มี Chrome และ assertions บางส่วนตรวจ command echo/โครงสร้าง/สีที่ต่างจากค่าหนึ่ง ไม่พิสูจน์ว่า formatter จบ, shell รันถูก cwd หรือ editor อ่านได้จริง ต้องมี packaged-native checks แยกบน Windows/macOS

Qualification, hostile suite, fidelity และ task eval ตรวจคนละ property: sentinel recall หรือ string matching ไม่ได้พิสูจน์ว่าระบบ reproduce/แก้/review บั๊กจริงได้ รายงานใหม่ต้องแยก source inspection, deterministic tests, integration, packaged E2E และ measured real-model workflows ไม่รวมเป็นคำว่า “ผ่านแล้ว” คำเดียว

## 5. ผลต่อแผน

รักษา Go core/context/receipts/adapters ที่ใช้ได้ แล้วเปลี่ยนจุดเชื่อม task → evidence → validation → learning → retrieval ให้ครบวงจร พร้อม document/runtime services และ Windows-native parity ไม่ควร rewrite ทุก package พร้อมกัน และไม่ควรเริ่มจากเปลี่ยน theme เพิ่มอีกรอบโดยยังใช้ lifecycle เดิม
