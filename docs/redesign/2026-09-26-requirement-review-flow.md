# Requirement → UX/UI preview → plan → confirmation

ปรับ flow เริ่มงานตามข้อสังเกตของผู้ใช้: คำสั่งงานจากหน้าแรกต้องเปิดแบบร่างให้ตรวจ ไม่ส่งเป็น agent turn ทันที

## Flow ที่ใช้จริง

1. **บอกความต้องการ** — ช่องเริ่มงานหลักใช้ปุ่ม “สรุปเป้าหมายและแผน” ส่วน “ถามคำถาม” เป็นทางเข้าแชทที่แยกชัด
2. **แก้แบบร่าง** — หน้า Plans รับข้อความเดิมเป็นเป้าหมายและเกณฑ์ร่าง ผู้ใช้แก้ผลที่คาดว่าจะเห็น/ใช้งานได้ เกณฑ์สำเร็จ ขอบเขต และข้อจำกัดก่อนสร้าง Task; การเปิดแบบร่างยังไม่สร้าง Session, Task หรือ Run
3. **สร้างแผน** — หลังบันทึก Goal ระบบเรียก planner หากมีโมเดลที่พร้อมใช้ ถ้าไม่มี โมเดลไม่ตอบ หรือแผนไม่ผ่านการตรวจ หน้าจอเก็บ Goal และแสดงทางสร้างแผนใหม่ โดยไม่เริ่มแก้ไฟล์
4. **ดูภาพรวมก่อนยืนยัน** — หน้าเดียวกันเรียงเป้าหมาย → ภาพที่คาดว่าจะได้ → เกณฑ์สำเร็จ → เหตุผล/ขั้นตอน/วิธีตรวจของแผน → ยืนยันหรือส่งกลับแก้ เมื่อไม่ได้กรอกภาพที่คาดไว้ เหตุผลที่ planner สร้างจะปรากฏแทน
5. **วนแก้** — แก้ Goal แล้ว revision ใหม่ทำให้แผนและการอนุมัติเดิมใช้ไม่ได้ ส่งแผนกลับแก้ต้องบอกเหตุผล; planner รอบใหม่ได้รับ feedback พร้อมขั้นตอนฉบับก่อน และแสดง diff ฉบับแผนให้ตรวจอีกครั้ง
6. **เริ่มตามแผน** — อนุมัติผูกกับ hash/revision ของแผนปัจจุบัน ฝั่ง Task engine ปฏิเสธ StartStep/BeginRun ก่อนอนุมัติ หลังอนุมัติยังเห็นแผนฉบับนั้นเป็นข้อมูลอ้างอิงและมีทางลัดไป action ถัดไป

## ข้อความบนหน้า

- “ภาพที่คาดว่าจะได้” เป็นคำอธิบายหน้าจอหรือเส้นทางใช้งานที่ผู้ใช้แก้ได้ ไม่ใช่หลักฐานว่าสร้างหน้าจอเสร็จแล้ว
- “แผนฉบับ N · รอตรวจ/ยืนยันแล้ว/ส่งกลับแก้” บอกสถานะของแผนที่เห็นอยู่
- “ยืนยันแผนเพื่อเริ่มงาน” ปลดล็อกขั้นทำงาน ยังไม่อ้างว่าผลงานเสร็จหรือผ่านการตรวจ
- กล่องตรวจความพร้อมปิดงานอยู่หลังแผนและการตัดสินใจ เพื่อไม่แทรกในช่วงตรวจแบบ

## หลักฐานตรวจรับ

- Chrome จริง: ทางเข้าหลักพาไปแบบร่าง โดยไม่มี Session หรือ Task ถูกสร้างก่อนบันทึก; แบบร่างบันทึกภาพที่คาดและบังคับ plan review; แผน pending ยังไม่แสดงปุ่มเริ่มแก้
- Chrome จริง: เห็น summary, เหตุผลแผนและปุ่มตรวจ/ส่งกลับแก้; หน้าจอ 390px ไม่ล้นแนวนอน; มีภาพ desktop/mobile ใน `.tmp-ui/plan-review-*.png`
- Engine: แก้ `experience_preview` หลังอนุมัติทำให้ต้องสร้างและตรวจแผนใหม่; rejected feedback อยู่ใน Task และถูกส่งเข้า planner รอบถัดไป

## ขอบเขตที่ต้องทำต่อใน v2

ทาง “ถามคำถาม” ยังเป็นแชททั่วไป ไม่ใช่ Task ที่ผูก Goal/Plan จึงไม่ควรใช้เป็นทางเริ่มงานที่ต้องมีแผนอนุมัติ การบังคับ policy เดียวกันกับทุก agent tool, native Windows, social และ Comfy endpoint ยังเป็นงานแยกของ release gate ทั้งระบบ
