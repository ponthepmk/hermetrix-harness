# ผลวัดและปรับปรุง Project Brain ของ Hermetrix

วันที่ 27 ตุลาคม 2026

Project Brain ที่ปรับตัวค้นแล้วช่วยให้ Bonsai Local ตอบขั้นตอนเฉพาะโปรเจกต์ได้ครบ 7 จาก 8 คำถาม เทียบกับ 1 จาก 8 เมื่อใช้ตัวค้นเดิม และ 0 จาก 8 เมื่อปิด Brain การวัดนี้ใช้บทเรียนที่ผ่าน curator แล้วหนึ่งเรื่องเกี่ยวกับ board project ID กับ Platform Project ID จึงเป็นผลนำร่องด้านการค้นและใช้ความรู้เฉพาะโปรเจกต์

นำตัวแก้เข้า source จริงแล้ว 4 ไฟล์ Go พร้อมข้อมูลทดสอบหนึ่งไฟล์ หลังนำเข้าผ่าน 1,435 test events ไม่มี failures, 20 test skips และผ่าน vet/build ตัวแอปที่ติดตั้งอยู่ยังไม่ได้อัปเดตในรอบนี้

## วิธีวัด

ใช้คำถาม 10 ข้อ: คำถามเกี่ยวกับบทเรียน 8 ข้อ และนอกเรื่อง 2 ข้อ แบ่งชุดออกแบบ 4 ข้อกับชุดกันไว้ 6 ข้อ ชุดกันไว้มีคำถามเกี่ยวข้อง 5 ข้อและนอกเรื่อง 1 ข้อ คำถามและเกณฑ์คะแนนถูกบันทึกก่อนเรียกโมเดลวัดคำตอบ ผู้เขียนตัวแก้ไม่ได้รับข้อความคำถามชุดกันไว้

เปรียบเทียบสามแบบกับคำถามเดิมทุกข้อ: ปิด Brain, ตัวค้นเดิม และตัวค้นที่ปรับแล้ว รวม Bonsai จริง 30 คำตอบ แบบละหนึ่งคำตอบต่อข้อ สลับลำดับสามแบบตามข้อเพื่อลดอคติจากลำดับรัน ใช้ provider/preset เดิม: context 16,384, output สูงสุด 3,072 และปิด reasoning ไม่มีการเพิ่มงบ profile

ค้นบริการ Pi จริงและอ่าน passage ตาม version ที่อ้างอิง แล้วเก็บผลเป็น snapshot เพื่อให้ทั้งสามแบบใช้เนื้อหาเดียวกัน Snapshot ผ่าน Retriever จริงที่ตรวจ scope/lifecycle/version, Context Compiler จริง และการ render ของ agent ก่อนส่งผ่าน provider service และตัวบันทึกการใช้ token ของ Hermetrix ไปยัง Bonsai Local การวัดคำตอบจึงไม่ได้วัดความหน่วงเครือข่าย Pi แบบปลายทางถึงปลายทาง

บทเรียนอ้างอิงคือ `reference/bind-a-board-project-before-adding-hermetrix-planning-tasks-2223d9b30c12.md` รุ่น `sha256:7f18e3102f70215acca3ef3238014e4970fa4f66cea6d4721b146c099a43f35b` โดยอ่านช่วง Solution/Problem ที่ดึงได้ตามรุ่นจริง ตัวเลข ID ในบทเรียนเป็นตัวอย่างในอดีต ไม่ใช่การยืนยัน ID หรือสิทธิ์ปัจจุบัน

## ผลคำตอบของ Bonsai

“ขั้นตอนครบ” หมายถึงระบุว่า task API ใช้ board project ID, ระบุทั้ง `list_platform_projects` และ `list_projects` และเชื่อมด้วยฟิลด์ `platform_project_id` คะแนนนี้แยกจากการจำตัวเลขตัวอย่างในอดีต

| ตัววัด | ปิด Brain | Brain เดิม | Brain ที่ปรับแล้ว |
|---|---:|---:|---:|
| คำตอบ JSON ตามรูปแบบ | 10/10 | 10/10 | 10/10 |
| ขั้นตอนเฉพาะโปรเจกต์ครบ | 0/8 | 1/8 | 7/8 |
| ขั้นตอนครบในคำถามที่กันไว้ | 0/5 | 0/5 | 4/5 |
| อ้างตัวเลขอดีตตรงกับ reference ที่ได้รับ | 0/8 | 2/8 | 7/8 |
| แยกคำถามนอกเรื่องได้ | 2/2 | 2/2 | 2/2 |

แบบปิด Brain ส่วนใหญ่ตอบว่าไม่มีข้อมูลพอ จึงไม่ได้ตีความคะแนน 0/8 ว่าเป็นการตอบข้อเท็จจริงผิด ตรวจ structured fields แล้วไม่พบการอ้างว่าได้ตรวจระบบสด หรือใส่ historical ID โดยไม่มี reference ทั้ง 30 คำตอบ ข้อนี้ไม่ใช่การตรวจว่าทุกประโยคในคำตอบปราศจากข้อผิดพลาด

## สิ่งที่แก้และสาเหตุ

ตัวค้นเดิมตัดคำถามเหลือช่วงต้นก่อนสร้างคำค้นสำรอง และหยุดแยกคำเมื่อเจอข้อความที่ไม่ใช่ ASCII ทำให้ชื่อ API ท้ายคำถามหรือชื่อ API ปนไทยหายไปก่อนค้น

ตัวแก้เก็บคำถามต้นฉบับไว้สำหรับ fallback ตรวจชื่อทางเทคนิคใน 4,096 อักขระแรก ให้ความสำคัญกับ identifier ที่มี underscore สูงสุดสองคำ ตัดคำซ้ำโดยไม่แยกตัวพิมพ์ และใช้คำทั่วไปสูงสุดสองคำเมื่อไม่มี identifier ไม่มีรายชื่อ API, ID, คำแปล หรือคำตอบของชุดวัดฝังอยู่ในโค้ด

ยังค้นสำรองได้ครั้งเดียวเฉพาะเมื่อผลแรกเป็น genuine no_match และยังตรวจ project, source, lifecycle, confidence, version และ passage เหมือนเดิม ไม่เพิ่ม model call สำหรับการสร้างคำค้น ตัวค้นร่วมนี้ยังถูกใช้โดยผู้เรียกเดิม รวมถึงเส้นทาง durable task ที่มีการผูก Project Brain แต่รอบวัดนี้ไม่ได้วัดผลลัพธ์การแก้โค้ดของ durable task

## ต้นทุนที่วัดได้

ตัวเลข token เป็นผลรวมของคำถาม 10 ข้อในแต่ละแบบ เวลาเป็นค่ามัธยฐานเฉพาะ model call ไม่รวมการค้น Pi และอาจได้รับผลจาก cache

| รายการ | ปิด Brain | Brain เดิม | Brain ที่ปรับแล้ว |
|---|---:|---:|---:|
| Prompt tokens | 2,214 | 4,046 | 8,178 |
| Output tokens | 1,173 | 1,289 | 1,622 |
| เวลา model call โดยประมาณ | 1.83 วินาที | 1.86 วินาที | 2.76 วินาที |

ประโยชน์ในชุดนี้แลกกับการส่งความรู้เข้าโมเดลมากขึ้นและคำตอบที่ยาวขึ้น ไม่ใช่ผลด้านความเร็ว งบสูงสุดต่อคำขอคงเดิม แต่จำนวน token ที่ใช้จริงเพิ่มขึ้น

ต้นทุนพัฒนาและตรวจทานแยกจากชุดวัด: native generation 10 calls ใช้ 24,249 prompt/11,349 output tokens; reviewer หนึ่ง call ใช้ 9,675/298 tokens ส่วนชุดวัด 30 calls ใช้ 14,438/4,084 tokens บันทึกทั้งหมดอยู่ในสถานะ reconciled และ usage_quality=actual ตรงกับผลโมเดลที่เก็บไว้

## การตรวจหลังเปลี่ยน

นำเข้าโค้ดผ่าน native write API ของ Hermetrix ครบ 4 receipts ไม่มี rollback ตรวจ ancestry ของผล Bonsai ที่ยอมรับ 9 ขั้น และตรวจ hash source ที่นำเข้าจริง ผู้ตรวจเป็น Bonsai อีก profile แต่ยังเป็นโมเดลเดียวกัน

ทั้งก่อนและหลังนำเข้า repository ผ่าน 1,435 test events, 0 failures, 20 test skips และ vet/build ผ่าน มี package ผ่าน 36 รายการและ package skip 8 รายการแยกจากตัวเลข test events ผลหลังนำเข้าใช้ source จริงโดยไม่มี source overlay

ไฟล์ 37 รายการจาก H1A8b ก่อนหน้ายังคง hash เดิม และ schema ยังคง 80 หลักฐานดิบ 284 artifacts ที่ตรวจ SHA-256 แล้วเก็บเฉพาะในเครื่องที่ `docs/evidence/2026-10-27/project-brain-measurement/` และไม่นำเข้า Git ดู [สรุปผลวัดที่อยู่ใน Git](../validation/2026-10-27-project-brain-pilot.json) และ [ผลตรวจ Harness](../validation/2026-10-27-harness-checkpoint.json)

## การใช้งานและงานถัดไป

สำหรับ workspace ที่ผูก Brain อยู่แล้ว ให้ใช้ตัวค้นที่ปรับแล้ว โดยใส่ชื่อ API หรือ component ในคำถามไทยเมื่อทราบชื่อ คงการรับรองความรู้โดย curator และการตรวจ reference ตามรุ่นไว้

ลำดับปรับปรุงต่อจากผลรอบนี้:

1. วัด fallback แปลงคำค้นไทยด้วย Bonsai เฉพาะกรณีค้นไม่พบ เทียบกับต้นทุนและงบสะสมเดิมก่อนเปิดใช้เป็นค่าเริ่มต้น
2. เพิ่มชุดวัดจากหลายบทเรียนและหลายปัญหาอิสระ เก็บโจทย์ใหม่ที่ไม่ใช้พัฒนาตัวค้น และรันซ้ำเพื่อประเมินความแปรปรวน
3. วัดงานแก้โค้ดจริงหลายไฟล์แบบเปิด–ปิด Brain ด้วยผลทดสอบ ไฟล์ที่แก้ รอบแก้ เวลา และค่าใช้จ่ายปลายทางถึงปลายทาง
4. เก็บผลใช้บทเรียนตาม version เป็น draft evidence แล้วให้ตรวจรับก่อนใช้เพิ่มความเชื่อมั่นหรือเลื่อนรุ่นความรู้

ผลหนึ่งบทเรียนกับคำถามหลายรูปแบบยังไม่พิสูจน์ว่าทำงานเขียนโค้ดทั่วไปดีขึ้น หรือเรียนรู้และเลื่อนรุ่นตัวเองครบวงจร
