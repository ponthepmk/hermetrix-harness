## Implementation and correctness

`store_fixture_test.go` runs actual production migrations once per test process
and captures only the closed pristine database bytes. Each caller writes those
bytes into its own temporary root and calls the unchanged production `store.Open`.
There is no shared live SQLite connection, test data, data-root lock or blob
directory. Each installation receives a distinct principal through a checked
update with foreign keys still enabled. Template bytes remain immutable in memory
and are regenerated by each newly built test process; no prebuilt database is
checked into the repository.

The image is read only after the final connection closes/checkpoints its WAL.
The current pristine database has no blob seeds; a future migration introducing
them fails explicitly until the fixture handles them. Updating a referenced
principal also fails rather than ignoring foreign-key constraints.

An isolation test compares actual SQLite table/index/trigger definitions and all
seeded row counts with a freshly migrated cold database. It checks seeded
ownership, distinct principals/roots, WAL, foreign keys, integrity, independent
settings/blob data and the real root lock. Agent fixture consumers retain their
original behavior assertions. Production `store` migration tests continue opening
fresh databases and upgrading real earlier schemas; they do not use this helper.
