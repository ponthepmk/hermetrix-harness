## Source and authority

The worker can enumerate only two to four named edits from a fully rederivable
version-one historical repair. It selects one existing edit and mechanically
retains the other proposed historical paths. It cannot invent replacement text,
drop ordinary changes, reduce exact-text edits, use partial file views, claim new
inference usage, or mark its output verified. Missing companions remain explicit
changes with the real current preimage/absence guard.

The coordinator requires an explicitly planned `proposal.reduce` scope. Existing
plans with the original five effects keep their original behavior. The planner
can include this sixth optional capability; all five original effects remain
required. A derivation is a separate host effect, never a fabricated
`provider.propose` call. Its result keeps the original native implementer identity
for independent-review checks, while artifacts and receipts identify the host
origin and zero new provider usage.

The native parent must have a complete observed proposal effect, a registered
verification failure, a checksum-bound mandatory failure log and a complete
rollback receipt. Task/project, frozen requirement ID/revision, criterion set,
ordered mandatory checks, source root, provider ID/revision and current input
preimages must match. A step name can change across replans; it is a label, not
write authority. Readonly selected files must also still match before derivation.

The stored envelope carries an optional versioned derivation proof. Loading it
rederives the entire result from its original native parent, including its input
hash and zero usage. Re-signed wrappers cannot select a different edit without
changing the result. Self references and chains of reduced parents are rejected
before recursive loading. Existing envelopes without proof retain their previous
canonical representation and replay behavior.

Each candidate consumes an ordinary attempt/action/deadline budget and passes
normal owner-authorized approval, apply, mandatory checks and post-test review.
Durable target history prevents retrying a previously derived target. Unknown or
partially persisted host effects require inspection; they are never dispatched
again as a fallback model call. No new schema or provider default is introduced.
