# Goal source creation and frozen-root qualification

Date: 2026-10-23. Follow-up to [durable goal control](2026-10-23-goal-runner.md).
The broad user goal remains active. This slice extends the source coding path;
it is not a deployed model/MetaTrader/remote-machine acceptance result.

## Problem and resulting behavior

The proposal loop previously required every selected file to exist. A goal could
repair source but could not create a requested EA or module from an absent leaf.
MQL extensions were also missing from source discovery.

Host snapshots now distinguish absent leaves from existing empty files. Only
exact owner-authorized writable paths can become absent candidates, within the
existing 32-file and source/secret constraints. Planner, selector and proposer
receive explicit absence information. Creates require full content, carry an
`absent` preimage and use atomic hard-link publication to avoid replacing an
intervening file. Parents must already exist; directory/delete scope is pending.
`.mq4`, `.mq5` and `.mqh` are now discoverable.

Failed creates roll back by moving exact generated bytes into a retained
same-directory quarantine. Receipts bind operation, path, generated hash and
observed absence; task rollback artifacts reference those receipts. Newer edits
cause a conflict. Failed multi-file receipt persistence rolls back every observed
write. Recovery requires both an exact artifact and intact quarantine inside the
expected parent. Missing, modified, unrelated or redirected evidence stays
uncertain rather than synthesizing success from an absent path.

Project roots can change through SaveProject. Goals now freeze canonical roots;
proposals and rollback snapshots retain that identity. Captured canonical paths
bind snapshots, batch writes, restoration and verification commands. A project
root switch therefore cannot redirect those operations into another directory.
One service serializes root edits and batch mutation per project. Inference stays
outside the lock. Other processes can update metadata, but operations use their
checked captured root rather than fetching a new target mid-mutation. This does
not claim kernel-level protection against arbitrary external filesystem changes.

## Observable acceptance

- Actual Node workflow starts with missing `sum.js`, creates incorrect code twice,
  fails the unchanged test twice, returns to verified absence twice, replans with
  saved failure evidence, then creates working code, verifies and completes.
  Model responses are simulated; files, SQLite and Node processes are real.
- Four concurrent absent-file writers yield one publication. A later owner-created
  file is retained and a stale goal proposal waits rather than overwriting it.
- An injected SQLite receipt failure after the second physical file publication
  restores both source paths to absence with retained quarantine receipts.
- Recovery reconciles intact evidence, but rejects modified quarantine, unrelated
  artifact kind, a changed project root and absence without a receipt.
- Changing the root before the next goal action causes zero provider/action
  dispatches. Changing it after proposal generation rejects apply. Changing it
  after apply rejects verification before launching a job; both original applied
  bytes and the new root are preserved, with no claimed rollback.
- Existing empty files remain distinct from absence. Unscoped/duplicate absence,
  secrets, traversal and missing parents are rejected.
