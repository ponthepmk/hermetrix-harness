## ต้นเหตุและการแก้ error

ตรวจใบรับผลของ `session_b3c2edd29222d470f1ea673bb2070050` พบ errorหลังอนุมัติเปิดเว็บไซต์แล้ว เส้นทาง audit เดิมมีการขอให้โมเดลแก้ batch ที่ผิดก่อน dispatch แต่แชตทั่วไปคืนerrorทันที เพิ่มการแก้ batch แบบจำกัดสองครั้งสำหรับแชตทั่วไป โดยบันทึก `tool_batch_rejected` และส่งคำแนะนำที่ผูกกับ turn เดิมกลับเป็น policy

ทั้งชุดที่ผิดถูกปฏิเสธก่อนบันทึก action/approval หรือทำเครื่องมือใด ๆ ไม่เลือกทำบางคำสั่งแทนโมเดล ไม่ replay effect ที่สำเร็จแล้ว คำขอใหม่ที่ต้องอนุมัติยังต้องผ่านผู้ใช้ และงบโมเดล/เครื่องมือ/loop detector เดิมยังมีผล

ทดสอบเส้นทางจริงของ core ด้วย model transport จำลอง: mixed read+approval→repair→รออนุมัติ โดยไม่มี read/effectจากชุดที่ผิด; และ approve effectแรก→mixed batchผิด→repair→คำตอบสำเร็จ โดยมี effect/receiptแรกเพียงครั้งเดียว Browserจริงผ่านคำขอ/login/ข้อมูลของ sessionผู้ใช้ผ่าน HTTPS แต่ไม่ได้ replay คำสั่งเก่าของผู้ใช้หรือยืนยันว่าโมเดลจะซ่อมทุก batch ได้

ใบรับผลเว็บไซต์เดิมยังบันทึก `Access Denied` จากปลายทางด้วย ซึ่งแยกจาก errorเรื่องหลายเครื่องมือ การปรับนี้ไม่เปลี่ยนผลหลักฐานเดิม
