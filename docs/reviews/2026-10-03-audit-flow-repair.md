# Hermetrix evidence audit workflow repair

Requested scope: repair the five harness shortcomings observed in the Hermetrix-only public O-Soul audit. Codex implements and verifies the local harness; Hermetrix performs any public website inspection. The website source and production deployment are outside this checkpoint.

## Observable acceptance

1. A spilled browser receipt can be read in full, including middle facts, without Codex relaying it. `context_search` v2 supports evidence references without enlarging the global fourteen-tool waist; audit sessions also expose `tool_result_read`. Reads resolve original receipts from the same session only, preserve Unicode, and paginate the entire encoded receipt below the inline ceiling using the turn's frozen token estimator.
2. Audit completion requires the successful `audit_report` receipt. Intent-only responses are recorded as progress and the loop continues; three non-final progress/rejection responses leave work explicitly incomplete. A report on the final permitted step still completes. A report requires successful current-turn browser evidence and rejects invented or failed citations.
3. An opt-in immutable `work_mode: audit` contract checks declared output capacity and configured output reserve (minimum 8,192 tokens), selects a larger reserve in the UI, caps cumulative usage at 180,000 tokens, and retains existing time, step, tool-call, qualification, egress and approval gates. Reasoning still shares the declared output cap; this is not a guarantee of 8,192 visible answer tokens. Near-budget requests expose only the report schema. Audit sessions have browser/history/skill-read/report tools; empty-root projects have no workspace file tools. Standard session budgets and legacy contract hashes remain compatible.
4. Approved browser clicks await bounded DOM/URL settling instead of a fixed 200ms delay. A real Chrome fixture changes routes after 350ms; the resulting URL and DOM must reflect that transition. Models are told to reread before subsequent input; stale observation guards and one-use approvals remain enforced. Settling is bounded, not a guarantee that every application finished all network activity.
5. Structured findings distinguish functional bugs, passive security configuration signals and observations, with confidence, original evidence references, observed behavior and recommendations. Verified bugs also require expected behavior and reproduction. Unchecked work is mandatory; passive header signals do not prove exploitability or overall site safety.
