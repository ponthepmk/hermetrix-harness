# O-SOUL: ผลทดสอบการกดใช้งานจริงและความชัดเจนของหน้าจอ

ทดสอบวันที่ 28 ตุลาคม 2026 บน [production ช่วงก่อนเปิดให้ลูกค้า](https://o-soul.go2gether-tech.online/) ตามคำขอเจ้าของระบบ ใช้เบราว์เซอร์จริงและบัญชี QA ที่มีอยู่ ไม่ใช่ผลจากอ่าน source หรือเรียก API อย่างเดียว ผู้ตรวจคือ Codex ผ่าน browser control; ผลนี้ยังไม่ใช่หลักฐานว่า Hermetrix/Bonsai ทำ UI loop เหล่านี้ได้เอง

**ผลหลัก:** เส้นทางซื้อสินค้าปกติและเส้นทางอัปโหลดภาพ 2D → สร้างกริด → แก้พิกเซล → บันทึก → พรีวิวเสื้อ → ซื้อชุดเม็ดกับเสื้อ → checkout → จ่ายแบบ Mock → รีเฟรชตรวจผล → ยกเลิก ทำจนจบได้ในข้อมูลที่ทดสอบ ไม่พบจุดตันที่กู้คืนไม่ได้ในสองเส้นทางนี้ พบปัญหา UX ที่ยืนยันแล้ว โดยควรแก้แถบเครื่องมือจอเล็กและสถานะคำสั่งซื้อที่ยกเลิกก่อนเปิดให้ลูกค้า

ยังสรุปว่า “ทุกหน้า ทุก flow พร้อมใช้งานจริง” ไม่ได้: ไม่ได้จ่ายเงินจริง ส่งสินค้าจริง ทำขั้นผลิต/หลังบ้าน การอนุมัติประกวด/การโหวต หรือใช้ AI แบบเสียโควตา

## สภาพแวดล้อมและวิธีตรวจ

- Desktop 1280×720, responsive mobile 390×844 และ 320×720 ในเบราว์เซอร์เดียวกัน ใช้ pointer/คีย์บอร์ด ไม่ใช่การรับรองบนโทรศัพท์จริงหรือทดสอบ pinch gesture จริง
- ตรวจภาพที่มองเห็นจริง สีข้อความ/พื้นหลัง ปุ่มและสถานะเลือก เปิด/ปิด modal ข้อความผิดพลาด ทางย้อนกลับ การบันทึกและรีเฟรช
- รอบแรกเก็บ 50 ภาพ และเพิ่ม 4 ภาพหลังอนุญาตส่งประกวด รวม 54 ภาพ พร้อม AX snapshots และ computed styles ในขั้นที่เกี่ยวข้อง หลักฐานดิบอยู่ local และถูก ignore จาก Git
- ไม่มี load test รอบใหม่ในงาน UI นี้ ผล load pilot ก่อนหน้าเป็นงานแยก อ่าน [รายงานเดิม](2026-10-28-osoul-authorized-read-load.md)
- โค้ด O-SOUL ที่อยู่ในเครื่องมีการแก้ไขอื่นอยู่ก่อนแล้ว การอ่าน source ใช้ช่วยอธิบายกลไกเท่านั้น ไม่ถือว่าเป็น revision เดียวกับ production ที่ยืนยันด้วย deployment hash

## สิ่งที่ควรแก้ ตามลำดับ

### UI-01 · P2: แถบเลือกสีใน editor ที่ 320px บีบข้อความจนอ่านไม่ได้

ทำซ้ำ: ตั้ง viewport 320×720 → เปิดผลงานที่บันทึก → ดูแถบด้านล่าง ปุ่มสีเหลือกว้างประมาณ 48.98px สูง 146px โดย span ที่ถือชื่อสีมีความกว้าง **0px** ข้อความช่วยเหลือแตกลงแนวตั้ง แถบกินพื้นที่วาดมากเกินจำเป็น

ผลกระทบ: ผู้ใช้แยกชื่อสีและความหมายของปุ่มได้ยาก ยังเปิด palette และกด “ตรวจผลงาน” ไปหน้าถัดไปได้ จึงไม่ใช่ hard blocker ที่ยืนยันแล้ว

แนวทาง: แบ่งแถบเป็นสองแถวบนจอแคบ ให้ปุ่มสีมีพื้นที่ข้อความขั้นต่ำ และย้าย CTA ถัดไปเต็มแถว หรือใช้ swatch + ชื่อสีสั้นพร้อม accessible name หลีกเลี่ยง grid ที่เหลือพื้นที่ให้ชื่อสีเป็นศูนย์ Source ในเครื่อง `apps/web/src/app/design/[id]/edit/page.tsx:827` ใช้ grid 4 คอลัมน์ โดย CTA/Undo/Redo กินพื้นที่ส่วนใหญ่ สอดคล้องกับ DOM ที่วัดได้

เกณฑ์รับ: 320/360/390px ชื่อสีอ่านได้อย่างน้อย A1/F19 ปุ่มไม่ทับกัน พื้นที่วาดยังใช้งานได้ เปิดสี/ปิดสี/Undo/Redo/ไปตรวจผลงานได้

### UI-02 · P2: หน้ารายละเอียดคำสั่งซื้อที่ยกเลิก สื่อสถานะไม่ชัด

ทำซ้ำ: จ่าย Mock → ยกเลิก → reload หน้ารายละเอียด แสดงกากบาทแดงและข้อความ “ชำระเงิน: สำเร็จ” ไม่มีคำว่า “ยกเลิกแล้ว” ส่วนรายการคำสั่งซื้อรวมแสดง “ยกเลิก” ถูกต้อง พบทั้งสองคำสั่งซื้อ QA

ผลกระทบ: ผู้ใช้อาจคิดว่ายังมีออร์เดอร์ที่ร้านต้องผลิตหรือจัดส่ง ไม่ได้พิสูจน์ว่าการยกเลิกล้มเหลวหรือมีบั๊กคืนเงิน Source ในเครื่อง `apps/web/src/app/orders/[orderNumber]/page.tsx:80` แยก icon ตามสถานะยกเลิก แต่ subtitle แสดงเฉพาะ paymentStatusLabel และซ่อน progress เมื่อ canceled

แนวทาง: แสดงข้อความ/ป้าย “ยกเลิกคำสั่งซื้อแล้ว” ชัดเจน แยกสถานะคำสั่งซื้อออกจากประวัติการชำระเงินและสถานะคืนเงินตามข้อมูลจริง ห้ามแสดงว่าคืนเงินแล้วโดยไม่มีหลักฐานจากระบบ

เกณฑ์รับ: หลังยกเลิกและรีเฟรช ทั้ง list/detail สื่อสถานะเดียวกัน โดยไม่ต้องอาศัยสีหรือกากบาทอย่างเดียว

### UI-04 · P3: ตัวเลือกสี/ไซซ์ในร้านค้าบอกสถานะผ่านภาพ แต่ไม่มีสถานะเลือกที่อ่านด้วยเครื่องได้

เสื้อดำ/M แสดงปุ่มม่วงชัด แต่ปุ่มที่ตรวจไม่มี `aria-pressed` หรือ radio state ส่วนพรีวิวสินค้ามี selected state ใน AX แล้ว จึงควรทำให้สอดคล้องกัน

## สี ข้อความ และพื้นหลัง

ภาพที่ตรวจ: ปุ่มหลักม่วง/ตัวอักษรขาว กล่องเนื้อหาขาว/ตัวอักษรเข้ม ข้อผิดพลาดคูปอง และ palette ที่เลือกมีความต่างที่มองเห็นได้ จุด editor 320px เป็นปัญหาพื้นที่ข้อความ ไม่ใช่ตัวอักษรขาวกลืนพื้นขาว เพราะ computed text จริงเป็นสีเข้มแต่กล่องกว้าง 0px

คำนวณ contrast จาก computed styles ที่รองรับได้ **502 ตัวอย่าง** ไม่พบต่ำกว่าเกณฑ์ที่ใช้ ตัวอย่างเหล่านี้มีรายการซ้ำระหว่างหน้าที่บันทึก ไม่ใช่ 502 controls ที่ไม่ซ้ำ เกณฑ์ข้อความปกติ 4.5:1 และข้อความใหญ่ 3:1 อ้างอิง [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

ตัวอย่างที่ไม่คำนวณ: สี oklab/oklch, gradient/ภาพพื้นหลัง, กลุ่มที่มี opacity, disabled/decorative และภาพเปลี่ยนสถานะกลาง animation จึงไม่ใช่การรับรอง contrast ทั้งเว็บ บางคำอธิบายมีขนาดเล็ก ควรตรวจซ้ำบนเครื่องจริงและภาวะแสงต่างกัน

Tab ที่ตรวจใน editor เห็น outline 2px ที่ปุ่มกลับและ CTA หลัก ไม่มี console warn/error ใน buffer ที่เรียกอ่านตอนจบ แต่ไม่ใช่หลักฐานว่าไม่มี error ตลอดระบบ **ยังไม่ได้ทดสอบ hover อย่างเป็นระบบ** เพราะ browser interface ที่ใช้ไม่มี hover API และไม่ได้ตรวจ screen reader หรือ keyboard-only ทุก flow
