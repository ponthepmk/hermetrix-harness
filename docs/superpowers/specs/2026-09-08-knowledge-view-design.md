# Knowledge view — design

วันที่ตกลง: 2026-09-08
สถานะ: spec รอ implement
ขอบเขต: spec ที่ 4 จาก 4 · มุมมอง Knowledge ตาม [spec 1](2026-09-01-shell-and-project-design.md) §3.1

## 1. ปัญหา

`data-view="knowledge"` ขึ้น "Not built yet. Waiting on spec 4" มาตั้งแต่ spec 1 ลง

spec 1 จองที่ไว้: rail = คลังและที่มา · main = ค้นหาและโน้ต · side = โน้ตที่เลือกและ backlink

## 2. สิ่งที่ตัดสินแล้ว

**โน้ตคือ `memories` ที่มีอยู่แล้ว ไม่ใช่ตารางใหม่**

`memories` มีครบ: `scope_kind` (user/project), `memory_kind`, `content`, `source`, `state`
พร้อม `GET /api/memories` · `POST /api/memories` · `POST /api/memories/{id}/archive`

**โน้ตแก้ไม่ได้ — archive แล้วเขียนใหม่**

นี่ไม่ใช่ข้อจำกัดที่ต้องแก้ มันคือกฎเดียวกับ Skill version: ของที่เคยมีผลต่อการตัดสินใจ
ต้องอ่านย้อนได้ว่าตอนนั้นเขียนว่าอะไร จอต้องแสดงเรื่องนี้ตรงๆ — ปุ่มชื่อ "แทนที่ด้วยฉบับใหม่"
ไม่ใช่ "แก้ไข" ที่ซ่อนว่าเบื้องหลังเกิดสองรายการ

**agent เขียนโน้ตเองไม่ได้** — `SaveMemory` ปฏิเสธทุกอย่างที่ `source != "user"`
สเปคนี้ไม่แตะกฎนั้น จอเขียนโน้ตได้เฉพาะเมื่อคนกดเอง

ทางเลือกที่ปฏิเสธ: ให้ agent สรุปบทสนทนาเป็นโน้ตอัตโนมัติ — จะกลายเป็นคลังที่โตเอง
โดยไม่มีใครรับผิดชอบความถูกต้อง และขัดกับ `candidate-first` ที่ทั้งระบบยึด

## 3. ค้นหา

### 3.1 ค้นอะไรได้บ้าง

| แหล่ง | มาจาก | สถานะ |
|---|---|---|
| โน้ต | `memories` | มี API แล้ว |
| Skill | `skills` + `skill_versions` | มี API แล้ว |
| Artifact | `artifacts` (CAS) | มี API แล้ว |
| ประวัติสนทนา | `agent_events` | มี `context_search` แล้ว |

### 3.2 semantic search ต้องต่อสายเพิ่ม

`event_embeddings` และ `skill_embeddings` มีแล้วและใช้งานจริง แต่ **`memories` ยังไม่เคยถูก embed**

เพิ่ม `memory_embeddings` ตามแพทเทิร์นเดียวกับ `skill_embeddings` เป๊ะ:

- key ด้วย **hash ของข้อความ** ไม่ใช่ id ของโน้ต — โน้ตที่ถูกแทนที่ด้วยฉบับใหม่ได้ vector ใหม่
  โดยไม่ต้องมีใครจำว่าต้อง invalidate และโน้ตสองใบที่เขียนเหมือนกันถูก embed ครั้งเดียว
- chunk ก่อน embed (โน้ตยาวได้ถึง 64 KiB — vector ของทั้งก้อนจะเจือจางจนหาไม่เจอ
  นี่คือสิ่งที่วัดไว้แล้วใน `internal/embedding`)
- ให้คะแนนเทียบ **ค่าที่สูงกว่าระหว่าง quartile ของผลลัพธ์เอง กับค่ากลางของ control**
  (`semanticControls` ใน `internal/agent/skillsemantic.go`) — floor คงที่โอนข้ามคำถามไม่ได้
  พิสูจน์มาแล้ว
- ไม่มี embedder = ถอยไปใช้ lexical เงียบๆ ไม่ใช่ error (กฎเดิมของทั้งระบบ)

**lexical กับ semantic รวมกัน ไม่ใช่แทนกัน** — เหตุผลเดียวกับ `context_search`:
ชื่อที่พิมพ์ตรงเป๊ะเป็น substring ที่ vector ทำได้แค่ประมาณ

## 4. โครงจอ

### 4.1 rail — คลังและที่มา

- **โน้ต** แยกตาม scope: ของฉัน (user) · ของโปรเจคนี้ (project)
- **Skill** (อ่านอย่างเดียว — จัดการจริงอยู่ที่ Skill Studio ใน Settings)
- **Artifact** ของโปรเจคนี้
- ตัวกรอง: เฉพาะที่ archive แล้ว (ค่าเริ่มต้นคือซ่อน แต่หาเจอได้เสมอ — ไม่มี hard delete)

### 4.2 main — ค้นหาและโน้ต

ช่องค้นบนสุด พิมพ์แล้วผลรวมทุกแหล่งใน §3.1 เรียงตามคะแนน แต่ละผลบอก **แหล่งที่มา**
ด้วยคำ ไม่ใช่ด้วยสีอย่างเดียว (เข้าถึงได้ตอนตาบอดสี — สอดคล้อง spec ผิว §2)

ไม่ได้พิมพ์อะไร = รายการโน้ตล่าสุดของ scope ที่เลือก

ปุ่ม "เขียนโน้ตใหม่" เปิดช่องเขียนในที่เดียวกัน ไม่ใช่ dialog ซ้อน

### 4.3 side — โน้ตที่เลือกและ backlink

- เนื้อโน้ตเต็ม, `memory_kind`, scope, เวลาที่สร้าง
- **backlink**: session ไหนเคยดึงโน้ตนี้เข้า context — อ่านจาก `agent_events`
  ไม่ต้องมีตารางความสัมพันธ์ใหม่
- ปุ่ม "แทนที่ด้วยฉบับใหม่" (archive เดิม + สร้างใหม่ในทรานแซกชันเดียว) และ "เก็บเข้าคลัง"
- ฉบับที่ถูกแทนที่เข้าถึงได้จากตัวกรอง archive พร้อมบอกว่าฉบับไหนมาแทน

## 5. panel `knowledge` ใน Chat

panel ย่อใน side ของมุมมอง Chat: ช่องค้นหาอย่างเดียว + ผล 5 อันดับ กดแล้วแทรกอ้างอิง
ลงช่องพิมพ์ หรือกระโดดไป Knowledge view

เหตุผล: ค้นโน้ตระหว่างคุยคือ use case จริง แต่การจัดการคลังต้องการความกว้าง

## 6. Error handling

- ไม่มีโน้ตเลย: บอกว่าคลังว่างและบอกว่าโน้ตเกิดจากคนเขียนเท่านั้น (agent เขียนให้ไม่ได้)
  ไม่ใช่จอว่าง
- embedder ไม่มี/ล่ม: ค้นด้วย lexical ต่อได้ พร้อมบอกว่าตอนนี้ค้นแบบตรงคำเท่านั้น
  — ผู้ใช้ต้องรู้ว่าผลที่ได้แคบลง ไม่ใช่คิดว่าไม่มีอะไรตรง
- โน้ตเกิน 64 KiB: ปฏิเสธตอนพิมพ์พร้อมบอกเพดาน ไม่ใช่ปฏิเสธตอนกดบันทึกหลังพิมพ์เสร็จ
- archive ล้มเหลว: ข้อความติดปุ่ม (spec 1 §8)

## 7. Testing

- `store`: `memory_embeddings` key ด้วย (text_hash, revision, chunk) · vector ของ revision
  ที่ไม่ตรงกันไม่ถูกนำมาเทียบ
- `product`: `SaveMemory` ยังปฏิเสธ `source != "user"` และ scope นอก user/project
  — mutation: ถอด guard แล้ว test ต้องแดง (นี่คือ authority ไม่ใช่ validation ธรรมดา)
- "แทนที่ด้วยฉบับใหม่": ฉบับเดิมยัง**อ่านได้** หลังถูกแทนที่ และชี้ไปฉบับใหม่ได้
- semantic: โน้ตภาษาไทยถูกหาเจอด้วยคำค้นภาษาอังกฤษที่ความหมายเดียวกัน วัดกับ embedder จริง
  (`HERMETRIX_EMBED_URL`) และ **skip เงียบเมื่อไม่มี embedder** ไม่ใช่ผ่าน
  — test ที่ผ่านตอนไม่มีโมเดลคือคำอ้างที่ไม่มีหลักฐาน
- ค้นแล้วไม่มีอะไรตรง: ได้ผลว่าง ไม่ใช่ผลที่ดีที่สุดในกองที่ไม่เกี่ยว
  (control anchor ทำงาน — mutation: ถอด control floor แล้วคำค้นที่ไม่เกี่ยวต้องเริ่มดึงผลมา)
- `ui_contract_test`: มุมมอง Knowledge ไม่มี "Not built yet" · ทุก id ถูก bind · ไม่มี `.style.`

## 8. นอกขอบเขต

- แก้โน้ตในที่เดิม (แทนที่ด้วยฉบับใหม่คือคำตอบ)
- โน้ตที่ agent เขียนเอง
- แท็ก/โฟลเดอร์ของโน้ต — `memory_kind` กับ scope พอสำหรับ v1
- sync คลังข้ามเครื่อง
