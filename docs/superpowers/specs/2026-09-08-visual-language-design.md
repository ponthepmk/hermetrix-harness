# Visual language — design

วันที่ตกลง: 2026-09-08
สถานะ: spec รอ implement
ขอบเขต: ผิวของทั้งแอป — สี ตัวอักษร ระยะห่าง ความลึก
ไม่ใช่: โครงจอ (ตัดสินแล้วใน [spec 1](2026-09-01-shell-and-project-design.md)) และไม่ใช่ฟีเจอร์ใหม่

## 1. ปัญหา

ผิวของแอปไม่เคยถูกออกแบบ มันสะสมมาทีละสี

`style.css` มี accent 6 เฉด (`cyan` `lime` `violet` `amber` `red` `blue`) ที่ไม่มีเอกสารไหน
อธิบายว่าอันไหนใช้เมื่อไหร่ ผลคือหน้าจอที่ **ดูเหมือนเครื่องมือ dev ยุค neon** ทั้งที่เนื้อหา
ข้างในเป็นงานเอกสาร งานแชท และงานอนุมัติ

หลักฐานที่วัดได้ (นับโดยตัดทุก `:root` block ออกก่อน — มี 4 block):
**hex 106 ค่า + `rgb()/rgba()` 88 ค่า = ค่าสีที่เขียนตรง 194 จุดนอกโทเคน** (hex ไม่ซ้ำ 90 ค่า)
ทุกค่าคือที่ที่สองที่ตอบคำถามว่า "สีนี้คืออะไร" และวันหนึ่งมันจะไม่ตรงกับ token

เจ้าของโครงการขอ: "เรียบๆ ใช้งานง่าย friendly ดูหรู" และเลือกโทน **มืด** (ไม่ใช่สว่าง ไม่ใช่ auto)

## 2. สิ่งที่ตัดสินแล้ว

**accent เดียว + สีสถานะสามสี** ไม่ใช่หกเฉดที่ไม่มีกฎ

เหตุผล: ความหรูมาจากความยับยั้ง ไม่ใช่จำนวนสี จอที่มีหกสีแข่งกันดึงสายตา ไม่มีอะไรเด่นจริง
เมื่อทุกอย่างเด่น สิ่งที่สำคัญจริง (ปุ่มอนุมัติ, สถานะพัง) ไม่มีที่ให้เด่นกว่า

**สีบอกสถานะเท่านั้น ไม่บอกหมวด** — Skill ไม่ได้มีสีของตัวเอง MCP ไม่ได้มีสีของตัวเอง
หมวดแยกด้วยตำแหน่งและหัวข้อ ซึ่งอ่านได้ตอนตาบอดสีด้วย

**ลดเส้น เพิ่มระดับพื้น** — ของเดิมแบ่งพื้นที่ด้วย `1px solid var(--line)` เกือบทุกที่
เส้นเยอะทำให้จอดูเป็นตาราง ใช้ระดับความสว่างของพื้นหลังแยกชั้นแทน เหลือเส้นเฉพาะที่ต้องการ
ขอบเขตจริง (ที่จับลาก, ช่องกรอกข้อความ)

## 3. โทเคน

### 3.1 พื้นและตัวอักษร

```
--bg          พื้นหลังสุด        ชั้น 0
--surface     การ์ด/panel        ชั้น 1
--surface-2   ยกขึ้นมา (hover, popover, ที่เลือกอยู่)   ชั้น 2
--line        เส้นเฉพาะขอบเขตจริง
--text        ข้อความหลัก
--muted       ข้อความรอง
--faint       ป้ายกำกับ/หน่วย
```

ต้องผ่าน **WCAG 2.2 AA**: `--text` บน `--bg` และบน `--surface` ≥ 4.5:1 ·
`--muted` ≥ 4.5:1 (ไม่ใช่ 3:1 เพราะมันเป็นข้อความ ไม่ใช่ของตกแต่ง) ·
`--faint` ≥ 3:1 และห้ามใช้กับข้อความที่ต้องอ่านเพื่อทำงานให้เสร็จ

ค่าที่ต้องวัดจริงตอน implement ไม่ใช่เดา — ดู §6

### 3.2 accent และสถานะ

```
--accent        สีเดียวของแอป: การกระทำหลัก, สิ่งที่เลือกอยู่, focus ring
--accent-soft   พื้นจางของ accent (ไม่ใช่สีที่สอง แค่ opacity ของสีเดียวกัน)
--ok            สำเร็จ/ผ่าน
--warn          รอ/ต้องตัดสินใจ/ใกล้เพดาน
--danger        ล้มเหลว/ทำลาย/ปฏิเสธ
```

**ยกเลิก:** `--accent-lime` `--accent-violet` `--blue` — ทุกจุดที่ใช้อยู่ต้องย้ายไปหา
accent เดียวหรือสีสถานะที่ตรงความหมาย ไม่ใช่ตรงความสวย

`--amber` → `--warn` · `--red` → `--danger` (เปลี่ยนชื่อให้บอกหน้าที่ ไม่ใช่บอกสี
ชื่อที่บอกสีคือชื่อที่ห้ามเปลี่ยนสี)

### 3.3 ระยะและรูปทรง

```
--space-1..6   4 8 12 16 24 32
--radius-sm    8px    ปุ่ม, ป้าย, ช่องกรอก
--radius       12px   การ์ด, panel
--radius-lg    16px   overlay, dialog
```

ของเดิมมี `--radius: 14px` ค่าเดียวใช้กับทุกขนาด การ์ดใหญ่กับป้ายเล็กจึงมนเท่ากัน
ซึ่งทำให้ของเล็กดูบวมและของใหญ่ดูแข็ง

### 3.4 ตัวอักษร

```
--text-xs / --leading-xs  12px / 1.4    ป้ายกำกับ, หน่วย, timestamp
--text-sm / --leading-sm  13px / 1.5    UI ทั่วไป
--text-md / --leading-md  14px / 1.6    เนื้อหาอ่าน
--text-lg / --leading-lg  16px / 1.5    หัวข้อ panel
--text-xl / --leading-xl  20px / 1.35   หัวข้อจอ
```

ระดับกลางชื่อ `--text-md` ไม่ใช่ `--text` เพราะ `--text` เป็นชื่อของ**สีข้อความ**อยู่แล้ว
โทเคนสองตัวที่ชื่อเดียวกันคือบั๊กที่รอเวลา

ทุกที่ที่ตั้ง `font-size` ต้องตั้ง `line-height` คู่กันเสมอ — ขนาดที่ไม่มี line-height
คือครึ่งเดียวของคำตอบ และจะไปยืมค่าจากที่อื่นโดยบังเอิญ

font stack เดิม (`Inter` แล้วค่อย system) **อยู่ที่เดิม** — Inter อ่านภาษาไทยไม่ได้ ระบบจะ
ตกไปใช้ฟอนต์ไทยของเครื่องอยู่แล้ว ซึ่งถูกต้องแล้วสำหรับ local-first ที่ไม่ควรโหลดฟอนต์จากเน็ต

## 4. โทเคนเวลา

**ไม่แตะ** `--dur-press` `--dur-arrive` `--dur-settle` `--dur-hold-done` `--dur-wait-pulse`
ตัดสินไปแล้วใน spec 1 §8.3 พร้อมเหตุผลว่าทำไมแต่ละตัวแยกกัน และ `ui_contract_test` บังคับอยู่

กฎเดิมที่ยังบังคับ: ห้ามเขียนวินาทีเป็นตัวเลขตรงใน `transition:`/`animation:` ·
ทุก block ที่เคลื่อนไหวต้องมีคู่ `prefers-reduced-motion` · เมื่อปิดการเคลื่อนไหว
ทุกสถานะยังต้องต่างกันด้วย **สีและคำ**

## 5. การย้าย

ทำเป็นรอบเดียว ไม่ผสมกับการเปลี่ยนโครงสร้าง — เปลี่ยนผิวอย่างเดียวแล้วดูผลก่อน

1. เขียน `:root` ชุดใหม่ทั้งชุด เก็บชื่อเดิมที่ยังใช้ได้ (`--bg` `--text` `--muted` `--line`)
2. เพิ่ม alias ชั่วคราวสำหรับชื่อที่ถูกยกเลิก (`--accent-lime: var(--accent)`) เพื่อให้ระหว่างย้าย
   จอไม่พัง แล้ว**ลบ alias ทิ้งในคอมมิตเดียวกับที่ย้ายที่ใช้สุดท้าย** — alias ที่ค้างคือหนี้
3. ไล่ hex ตรง 121 จุดออกให้หมด แต่ละจุดตอบว่ามันคือ token ไหน ถ้าไม่มี token ไหนตรง
   แปลว่าเจอความหมายที่ยังไม่มีชื่อ ให้ตั้งชื่อ ไม่ใช่ปล่อย hex ไว้
4. `--radius` เดี่ยว → สามระดับ
5. ระยะห่าง: ไล่ padding/gap ที่เขียนตัวเลขตรงให้ไปใช้ `--space-*`

## 6. Testing

- `ui_contract_test`: ค่าสีที่เขียนตรงนอก `:root` (hex + `rgb()/rgba()`) **มีเพดานที่ลดได้อย่างเดียว**
  เริ่มที่ 194 ลดลงทุกคอมมิตจนเป็น 0 — ห้ามเพิ่ม
- `ui_contract_test`: ไม่มีชื่อโทเคนที่ยกเลิกแล้วเหลืออยู่ (`--accent-lime` `--accent-violet` `--blue`)
- **contrast วัดจริงด้วยโค้ด ไม่ใช่สายตา**: test อ่านค่า hex จาก `:root` แล้วคำนวณ
  contrast ratio ตาม WCAG — `--text`/`--bg`, `--text`/`--surface`, `--muted`/`--surface` ≥ 4.5
  · `--faint`/`--surface` ≥ 3.0 · mutation: ทำ `--muted` ให้จางลงหนึ่งขั้นแล้ว test ต้องแดง
- โทเคนเวลาและคู่ `prefers-reduced-motion`: กฎเดิมของไฟล์นี้ยังบังคับครบ
- ตรวจในเบราว์เซอร์จริง 1280×800 และ 1600×1000: ไม่มี horizontal overflow ทุกมุมมอง
  (กฎเดิมจาก spec 1)
- ปิด CSS transition ทั้งหมด (`prefers-reduced-motion: reduce`) แล้วยังแยก
  hover/active/disabled/loading ออกจากกันได้

## 7. นอกขอบเขต

- โหมดสว่างและ auto ตาม system — เจ้าของเลือกมืดอย่างเดียว โครงโทเคนรองรับได้ทีหลัง
  โดยไม่ต้องรื้อ (สลับค่าใน `:root` ชุดเดียว) แต่ยังไม่ทำตอนนี้
- ฟอนต์ไทยที่ฝังมากับแอป — ยังใช้ฟอนต์ของเครื่อง
- ไอคอนชุดใหม่
