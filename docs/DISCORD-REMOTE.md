# ควบคุม Hermetrix ผ่าน Discord

รุ่นนี้ใช้บอตที่เชื่อมออกจากเครื่องไปยัง Discord Gateway แล้วรับ slash commands โดยใช้โปรเจกต์ โมเดลบนเครื่อง เซสชัน และการอนุมัติของ Hermetrix ไม่ต้องเปิดพอร์ตเว็บแอปสู่อินเทอร์เน็ต

ค่าเริ่มต้น **ปิดอยู่** ต้องตั้งค่าและกดเชื่อมต่อเอง ไม่มี token หรือบัญชี Discord ตัวอย่างที่ใช้เชื่อมต่อได้จริง

## การตั้งค่า

1. เปิด **Settings → Discord remote** ใน Hermetrix
2. ไปที่ [Discord Developer Portal](https://discord.com/developers/applications) สร้าง Application ของคุณ คัดลอก **Application ID** แล้วสร้าง Bot และนำ **Bot token** มาใส่ในช่องรหัสของ Hermetrix
3. ใน Discord เปิด **User Settings → Advanced → Developer Mode** แล้วคัดลอก Server ID, Channel ID และ User ID ตาม [คู่มือ Discord](https://support.discord.com/hc/en-us/articles/206346498-Where-can-I-find-my-User-Server-Message-ID)
4. ใส่ ID ของเซิร์ฟเวอร์ ห้องส่วนตัว และบัญชีที่อนุญาต หนึ่งรายการต่อบรรทัดหรือคั่นด้วย comma ต้องกำหนดครบทั้งสามประเภท ไม่รองรับ `*` หรือการเปิดให้ทุกคน
5. เลือกโปรเจกต์หนึ่งรายการ โมเดล localhost ที่พร้อม และขนาดบริบทที่ผ่านเงื่อนไข ถ้าต้องการบริบทที่ใหญ่ขึ้น ให้ตรวจโมเดลใน Models ก่อน ระบบไม่สร้าง qualification override ให้เอง
6. กด **บันทึกขอบเขต** แล้วกรอกและกด **บันทึก Token** ช่อง token จะถูกล้างหลังส่ง และไม่แสดงค่ากลับจาก API
7. เปิดลิงก์เชิญบอตที่หน้าเดียวกัน ลิงก์ใช้ `bot` และ `applications.commands` โดยไม่ขอ Administrator
8. ใน Developer Portal **เว้น Interactions Endpoint URL ว่าง** เพื่อรับ interactions ทาง Gateway ตาม [เอกสาร Discord](https://docs.discord.com/developers/interactions/receiving-and-responding) ไม่ต้องเปิด Message Content Intent สำหรับ slash commands นี้
9. กด **เชื่อมต่อ Discord** รอให้แสดงว่าเชื่อมต่อแล้ว จึงลอง `/hermetrix new` และ `/hermetrix ask` ในห้องที่อนุญาต

ต้องเปิด Hermetrix และ local model server ทิ้งไว้ การบันทึกขอบเขตหรือเปลี่ยน token จะหยุดการเชื่อมต่อเดิม ยกเลิกการผูกเซสชันและ preview อนุมัติเดิมของ Discord และต้องกดเชื่อมต่ออีกครั้ง ประวัติเซสชันยังเปิดดูได้ในแอป ปุ่มหยุดเชื่อมต่อปิดการเชื่อมต่ออัตโนมัติด้วย ส่วนการปิดและเปิดโปรแกรมตามปกติจะกลับมาเชื่อมเฉพาะเมื่อเคยเปิดใช้งานไว้

## คำสั่ง

| คำสั่ง | ผล |
|---|---|
| `/hermetrix new` | เปิดเซสชันใหม่ของโปรเจกต์และโมเดลที่ตั้งไว้ |
| `/hermetrix ask prompt:...` | ส่งงานให้โมเดลในเซสชันของผู้ใช้และห้องนั้น |
| `/hermetrix status` | ดูสถานะ คำตอบล่าสุด และรายการที่รออนุมัติ |
| `/hermetrix approve approval_id:...` | อนุมัติคำขอที่ระบบแสดงให้ผู้ใช้คนนั้นตรวจแล้ว แบบครั้งเดียว |
| `/hermetrix deny approval_id:...` | ปฏิเสธคำขอที่รออนุมัติ |
| `/hermetrix cancel` | ขอหยุด request ของตนที่กำลังทำผ่าน bridge การกระทำที่ทำสำเร็จแล้วไม่ได้ถูกย้อนกลับ |

ตัวอย่าง prompt: `อ่านไฟล์และวางแผนแก้บั๊กก่อน ยังไม่เขียนไฟล์` หรือ `แก้ฟังก์ชันนี้แล้วรันทดสอบที่มีอยู่ ห้ามแก้เทสต์เพื่อให้ผ่าน` เป็นคำสั่งใน chat agent การสร้าง durable plan และการตรวจอิสระแบบครบขั้นยังใช้หน้า Plans

คำตอบส่งเป็น ephemeral reply ให้ผู้เรียกคำสั่ง ไม่ broadcast ลงห้อง และปิดการ ping จากข้อความโมเดล คำตอบยาวจะตัดพร้อมบอกให้เปิดแอปเพื่ออ่านครบ หาก preview ของการอนุมัติยาวเกินกว่าจะแสดงครบ จะให้ตรวจและอนุมัติในแอป

## ขอบเขตข้อมูลและสิทธิ์

- โมเดลอยู่บนเครื่อง แต่ข้อความที่พิมพ์ คำตอบ และ preview ที่ส่งกลับ **ผ่านบริการ Discord** เลือกโปรเจกต์และห้องให้เหมาะกับข้อมูลที่ต้องการส่ง
- ต้องตรงทั้ง application, server, channel และ user allowlist บัญชี bot และ DM ไม่ได้รับสิทธิ์ในรุ่นนี้
- เซสชันแยกตาม server/channel/user และผูกกับเจ้าของในเครื่อง โปรเจกต์ provider และ context profile ผู้เรียกคำสั่งไม่สามารถป้อน session ID ของคนอื่นเพื่อสลับงานได้
- คำสั่งที่ Discord ส่งซ้ำจะไม่เรียกงานซ้ำ ข้อผิดพลาดหลังส่งงานจะไม่ทำให้ระบบเดาการอนุมัติหรือ replay ผลข้างเคียงเอง
- การอนุมัติผูกกับ ID และ hash ของคำขอเดิม พร้อมผู้ใช้/ห้องที่ได้รับ preview ไม่เปลี่ยนเป็นสิทธิ์ถาวร
- Token อยู่ใน credential vault ของเครื่อง บน Windows ใช้การป้องกันของ Windows ไม่เก็บ token ลง SQLite, output API หรือ log และไม่เก็บ token ไว้ใน JavaScript หลังบันทึก

## แก้ปัญหา

| อาการ | ตรวจ |
|---|---|
| ยังไม่เปิดใช้งาน | บันทึกขอบเขตและ token แล้วกดเชื่อมต่อ |
| HTTP 401 / connection code 4004 | token ไม่ถูกต้องหรือถูก reset ใส่ token ใหม่จาก Bot page |
| HTTP 403 | บอตอยู่ในเซิร์ฟเวอร์ที่ระบุหรือไม่ และ Application ID ตรงกับ token หรือไม่ |
| ไม่เห็น `/hermetrix` | เชิญด้วย `applications.commands`, ตรวจ Server ID และสิทธิ์ใช้คำสั่งของห้อง จากนั้นตรวจสถานะการลงทะเบียน |
| คำสั่งถูกปฏิเสธ | ตรวจ Server/Channel/User ID ให้ตรง บัญชีที่อนุญาตต้องเป็นผู้ใช้ ไม่ใช่บอต |
| เชื่อมต่อแล้วแต่ไม่มีคำตอบจากบอต | Interactions Endpoint URL ต้องว่างสำหรับ Gateway mode; ตรวจโมเดล local และใช้ `/hermetrix status` |
| บอกให้ตรวจในแอป | คำตอบหรือ approval preview ยาวเกินขอบเขต หรือการอนุมัติเดิมหมดอายุ/ไม่ตรงเซสชัน |
| ต้องการใช้ DM | รุ่นนี้รับเฉพาะห้องในเซิร์ฟเวอร์ที่กำหนด ยังไม่รับ DM |

การตรวจ automated ใช้ Discord Gateway/REST จำลองในเครื่องและ agent จริงกับ provider fixture เพื่อพิสูจน์เส้นทางโปรโตคอล สิทธิ์ และการอนุมัติ การยืนยันว่าเชื่อมกับบัญชีของผู้ใช้ได้จริงต้องมีบอตและ ID จริง และต้องเห็นสถานะ Ready พร้อมผลจาก slash command บน Discord
